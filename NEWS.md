# ontologyConnectR 0.2.1

* sqlglotR is now declared in `Suggests`, and ontologySpecR is added to
  `Suggests`. Both are listed in `Remotes`.
* `live_jdbc()` connections now warn (once per session and dialect) when the
  target `dialect` isn't `"duckdb"` but SQL can't be translated, because
  sqlglotR isn't installed or its Python `sqlglot` module is missing.
  Previously the DuckDB SQL was sent silently.
* `conn_from_bundle()` accepts either an object type or a bundle plus an
  object type id (`conn_from_bundle(bundle, "Patient")`), resolved with
  `ontologySpecR::bundle_object_type()`. The old
  `conn_from_bundle(object_type, credentials)` call still works.
* `conn_from_bundle()` now defaults the source resource to
  `ontologySpecR::object_table()` (the object type's `source$table`, else its
  id) instead of `tolower(id)`. Set `live_source$params$resource` to keep a
  different name. `live_source$params$driver_path` is now passed to
  `live_jdbc()`.
* The `live_source` extension fields are documented in the README.
* Package structure fixes, so the package builds, loads and passes
  `R CMD check`:
  * The backends moved from `R/backends/*.R` to `R/backend-*.R`. R ignores
    subdirectories of `R/`, so `live_rest()`, `live_fhir()`, `live_jdbc()` and
    `live_icij()` were never actually loaded.
  * Removed the stray `useDynLib()` (the package has no compiled code).
  * NAMESPACE and `man/` are now generated by roxygen2. `print()` for
    `OntologyContext` and the `os_collect()` methods are now registered, and
    `os_collect()` is exported.
  * Live connections declare dbplyr's 2nd edition backend interface, which
    current dbplyr needs for `dplyr::tbl()`.
  * Fixed `map_from_source()` failing on result columns not in the schema
    map, and `map_to_source()` returning a named `select` vector.
* The `live_rest()` docs now show `objectSetsR::object_set()` as an example of
  use, not as a dependency.
